## 1. 用户故事

作为 **平台管理员**，
我希望 **在不影响现有知识库查询体验的前提下，更新系统默认 Embedding 模型**，
以便 **在 AI 模型升级时能够平滑过渡，不会因为强制重建导致业务中断**。

作为 **知识库管理员**，
我希望 **对每个知识库选择是否迁移到新 Embedding 模型，或锁定在当前版本**，
以便 **根据业务价值灵活控制迁移成本和风险**。

作为 **终端用户（Chat 提问者）**，
我希望 **在管理员开启时能看到检索结果的技术细节（来源模型、匹配度等）**，
以便 **对检索质量有更好的可观测性**。

## 2. 验收标准

### 2.1 系统默认模型变更

| ID | 角色 | 操作 | 预期结果 |
|----|------|------|---------|
| AC-01 | 平台管理员 | 在 /model/management 修改"知识库默认embedding模型" | 系统保存新默认模型；已有知识库**不受影响**；新建知识库自动使用新模型 |
| AC-02 | 平台管理员 | 变更默认模型后，进入影响分析页 | 展示所有已有知识库的迁移状态（待迁移 / 迁移中 / 已完成 / 已锁定）；显示预估重建时间；页面自动刷新最新状态 |

### 2.2 知识库迁移策略

| ID | 角色 | 操作 | 预期结果 |
|----|------|------|---------|
| AC-03 | 知识库管理员 | 点击知识库的"立即迁移"按钮 | 后台开始重建向量；知识库状态变为"迁移中"；查询时自动启用双模型 RRF 融合 |
| AC-04 | 知识库管理员 | 点击知识库的"稍后迁移"按钮 | 知识库保持原模型；不受系统默认变更影响；可随时重新发起迁移 |
| AC-05 | 知识库管理员 | 点击知识库的"锁定当前模型"按钮 | 知识库锁定当前 embedding 模型；不再出现在系统默认变更的影响范围内；查询仅使用锁定时的模型 |
| AC-06 | 知识库管理员 | 在迁移过程中点击"暂停迁移" | 迁移暂停；已重建部分保留；查询时对已重建部分使用新模型，未重建部分使用旧模型 |
| AC-07 | 知识库管理员 | 在迁移过程中点击"强制完成" | 立即结束迁移；已完成部分切换到新模型；未完成部分标记为失败 |

### 2.3 查询路由策略

| ID | 句型 | 验收标准 |
|----|------|---------|
| AC-08 | WHEN 知识库处于"迁移中"状态, THE SYSTEM SHALL | 对该知识库的查询同时使用新旧两个 embedding 模型，结果通过 Reciprocal Rank Fusion (RRF) 合并 |
| AC-09 | WHEN 知识库处于"已完成"状态, THE SYSTEM SHALL | 仅使用新模型查询，不再调用旧模型 |
| AC-10 | WHEN 知识库处于"已锁定"状态, THE SYSTEM SHALL | 仅使用锁定时的模型查询 |
| AC-11 | WHERE 管理员开启"显示技术细节", THE SYSTEM SHALL | 在 Chat 界面展开技术详情面板，显示：来源知识库、使用的 embedding 模型、检索文档数、匹配度 |

### 2.4 查询策略配置

| ID | 角色 | 操作 | 预期结果 |
|----|------|------|---------|
| AC-12 | 平台管理员 | 在系统设置中设置查询路由策略为"仅使用新模型" | 所有知识库的查询仅使用当前配置的 embedding 模型 |
| AC-13 | 平台管理员 | 在系统设置中设置查询路由策略为"双模型 RRF 融合" | 迁移中的知识库使用双模型 RRF；已完成/锁定的知识库按各自状态独立处理 |
| AC-13b | 平台管理员 | 在系统设置中设置查询路由策略为无效值 | 返回 400 错误；提示可选值：`new_only` / `old_only` / `dual_rrf` |
| AC-14 | 平台管理员 | 在系统设置中关闭"显示技术细节" | Chat 界面不显示技术详情折叠面板 |

### 2.5 错误处理

| ID | 异常场景 | 预期结果 |
|----|---------|---------|
| AC-15 | 迁移过程中新模型 embedding 服务不可用 | 暂停迁移任务；记录错误日志；查询降级为仅使用旧模型；管理员收到通知 |
| AC-16 | 迁移过程中旧模型 embedding 服务不可用（已锁定场景） | 返回错误提示；管理员可选择解除锁定或更换模型 |
| AC-17 | 知识库文档量超大（> 100,000）时发起迁移 | 提示预估重建时间；管理员确认后才执行；提供分期迁移选项 |

## 3. 边界情况

- **系统默认模型变更时，已有知识库不会被迫迁移** — 这是核心设计原则
- **迁移中断（如服务重启）**：重启后从上次完成的进度继续，不重新开始
- **双模型 RRF 融合的延迟增加**：控制在 200ms 以内，用户无感知
- **锁定状态的解除**：解除后知识库恢复为"待迁移"状态，可重新发起迁移
- **多个知识库同时迁移**：支持并发迁移任务，各自独立进度
