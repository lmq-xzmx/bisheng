## 3. 问题发现与方案讨论

### 问题 1：向量兼容性问题

**发现**：不同 embedding 模型生成的向量在语义空间不兼容。更换模型后：
- Milvus 中存储的旧向量与新查询完全不匹配
- 旧向量变成语义垃圾，查询结果严重降级
- 系统显示"已切换到新模型"，但实际向量仍是旧的

### 方案对比

| 方案 | 做法 | 风险 |
|------|------|------|
| A. 仅同步新建知识库 | 撤销自动同步逻辑，已有知识库不受影响 | 最安全，但不灵活 |
| B. 同步 + 标记待重建 | 自动同步 + 标记"待重建"状态 | 中等，需人工触发重建 |
| C. 强制重建 | 同步 + 自动触发 re-embed | 生产环境慎用 |
| D. 模型别名/路由层 | 换模型不改向量，查询时双模型融合 | 临时方案，最终仍需重建 |

### 方案确定过程

- **用户否定 C**：暴力重建会影响业务表现
- **用户倾向 B + D 结合**：平滑迁移，迁移期间可查询
- **用户关注点**：
  1. 大文档集体量时的用户体验
  2. 迁移期间终端用户 Chat 场景的感知
  3. 查询数据溯源（是否记录由哪种 embedding 提供支持）

### 最终确认方案：ABD 综合

```
A 的安全：新建知识库用新模型，已有知识库不被迫切换
B 的灵活：允许用户主动迁移，并知道影响
D 的平滑：迁移期间仍可查询，不影响业务
```

## 4. 关键技术决策（已确认）

### 决策 1：查询合并策略
- **选定**：Reciprocal Rank Fusion (RRF)
- **原因**：新旧向量空间不兼容，RRF 只依赖排名不依赖分数，业界标准（Elasticsearch、Weaviate 在用）

### 决策 2：锁定粒度
- **选定**：知识库级别（per knowledge base）
- **原因**：不同知识库有不同业务价值，需灵活控制迁移成本

### 决策 3：延迟控制
- **选定**：接受 1.5x 延迟（< 200ms，用户无感知）
- **原因**：embedding 服务调用时间约 100ms，双模型约 150ms，仍在无感知范围

### 决策 4：技术细节显示
- **新增后台开关**：`show_embedding_details`
- **效果**：管理员开启后，终端用户可在 Chat 界面展开技术详情面板

### 决策 5：查询路由策略
- **新增后台开关**：`embedding_query_strategy`
- **选项**：
  - `new_only`：仅使用新模型
  - `old_only`：仅使用旧模型
  - `dual_rrf`：双模型 RRF 融合（默认）

## 7. 重建时间估算（业内实践）

| 文档规模 | 典型文档数 | 重建耗时（CPU） | 重建耗时（GPU） |
|---------|-----------|----------------|----------------|
| 小型知识库 | ~1,000 篇 | 10–30 分钟 | 2–5 分钟 |
| 中型知识库 | ~10,000 篇 | 2–6 小时 | 20–40 分钟 |
| 大型知识库 | ~100,000 篇 | 1–3 天 | 2–8 小时 |
| 超大知识库 | 500,000+ 篇 | 1–2 周 | 1–3 天 |

**用户可接受范围**：
- 1–3 小时：可接受
- 1–3 天：犹豫
- 超过 3 天：谨慎评估

## 8. RRF 算法原理

```
原理：
  新模型召回 Top-10：文档A(0.92), 文档B(0.88), 文档C(0.75)
  旧模型召回 Top-10：文档C(0.95), 文档D(0.91), 文档A(0.89)
  
  RRF 合并（排名加权）：
    文档A: 1/1 + 1/3 = 1.33  → 排名 #1
    文档C: 1/3 + 1/1 = 1.33  → 排名 #1 (并列)
    文档B: 1/2               → 排名 #3
    文档D: 1/2               → 排名 #3 (并列)
```

## 9. 已 revert 的危险代码

```python
# 以下代码已被移除，因为它会直接修改已有知识库的 model 字段，
# 但不触发向量重建，导致"显示新模型但向量仍是旧的"不一致状态

@classmethod
async def _sync_knowledge_embedding_model(
    cls,
    tenant_id: int,
    new_embedding_model_id: int,
) -> None:
    """Sync all existing knowledge bases to use the new embedding model."""
    from bisheng.knowledge.domain.models.knowledge import KnowledgeBase

    async with get_async_db_session() as session:
        stmt = sql_update(KnowledgeBase).where(
            KnowledgeBase.tenant_id == tenant_id,
            KnowledgeBase.model != str(new_embedding_model_id),
        ).values(model=str(new_embedding_model_id))
        await session.exec(stmt)
        await session.commit()
```
